# Bob Debug Pipeline

AI-powered debugging and testing workflow built with **IBM Bob 2.0**.

The project demonstrates how an AI-assisted developer workflow can reduce the manual effort required to investigate a bug, understand its root cause, generate a regression test and fix, validate the result, and prepare the changes for a GitHub pull request.

---

## Problem

Developers often spend significant time manually:

- Investigating failing tests
- Reading stack traces and unfamiliar code
- Identifying the root cause
- Writing regression tests
- Implementing fixes
- Running validation tests
- Preparing changes for code review

This workflow can be repetitive and error-prone, especially when debugging small but recurring issues.

---

## Solution

**Bob Debug Pipeline** demonstrates an AI-assisted debugging workflow using IBM Bob.

The MVP follows this pipeline:

```text
Bug / Stack Trace
        ↓
Repository Analysis
        ↓
Root Cause Detection
        ↓
Regression Test
        ↓
Fix Generation
        ↓
Test Validation
        ↓
GitHub Pull Request
```

IBM Bob is used as a core part of the debugging and implementation workflow.

---

## MVP

The MVP focuses on a small Node.js project containing a realistic Jest test failure.

### Bug scenario

The application contains a `getUserById()` function:

```javascript
function getUserById(id) {
  return users.find(user => user.id === id);
}
```

The test expects:

```text
getUserById(999) → null
```

However, JavaScript's `Array.find()` returns:

```text
undefined
```

when no matching element is found.

Therefore, the test fails with:

```text
Expected: null
Received: undefined
```

### Root cause

The implementation relies directly on `Array.find()` without normalizing the result.

### Fix

IBM Bob identified the minimal fix:

```javascript
return users.find(user => user.id === id) ?? null;
```

This preserves the existing behavior for valid users while returning `null` when the requested user does not exist.

---

## IBM Bob Workflow

The debugging workflow was performed using IBM Bob 2.0.

### 1. Investigation

Bob was asked to:

- Inspect the relevant files
- Analyze the failing Jest test
- Reproduce or understand the failure
- Identify the root cause
- Propose a minimal fix

No files were modified during the investigation phase.

### 2. Implementation

Bob was then instructed to:

- Modify only `test-project/src/userService.js`
- Implement the proposed minimal fix
- Avoid unrelated changes
- Run the focused Jest test
- Report the final validation result

The resulting fix was:

```javascript
return users.find(user => user.id === id) ?? null;
```

## Application Workflow

The React frontend presents the debugging workflow as a single developer-oriented interface.

### 1. Bug / Stack Trace

Displays the failing Jest scenario:

```text
Expected: null
Received: undefined

File:
tests/userService.test.js

Test:
getUserById(999)
```

### 2. Root Cause Analysis

Displays the root cause identified during the Bob debugging workflow.

### 3. Regression Test

Displays the regression scenario that validates the expected behavior.

### 4. Fix Generated by Bob

Displays the minimal code change:

```diff
- return users.find(user => user.id === id);
+ return users.find(user => user.id === id) ?? null;
```

### 5. Test Validation

Displays the successful Jest validation:

```text
2 tests passed
```

### 6. GitHub Pull Request

The workflow includes a GitHub PR step in the demo interface.

The current MVP demonstrates the PR workflow in the UI. The actual repository pull request was created separately through GitHub during development.


- Bug information
- Root cause

- Validation result
